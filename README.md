# CLNUP — интерфейс и сервер

Полный локальный проект: Node.js 22.20+, TypeScript, Express 5, PostgreSQL 16,
Prisma 6, Zod, Argon2id, серверные сессии, постоянные фотографии и ручная
модерация. HTML сохранён в `public/index.html`; демонстрационные обработчики
полностью заменены `public/app.js`. Интерфейс и API работают с одного адреса.

## Быстрый запуск (Docker Desktop / Docker Compose v2)

Распакуйте архив, откройте терминал в каталоге `clnup-server`:

```bash
node scripts/setup.mjs
docker compose up --build -d
```

Первая команда создаёт `.env` со случайными паролем PostgreSQL и ключом сессий.
Повторный запуск не перезаписывает существующие секреты. Если Node.js на хосте
не установлен, генератор можно запустить контейнером:

```bash
docker run --rm -v "${PWD}:/app" -w /app node:22.20.0-bookworm-slim node scripts/setup.mjs
docker compose up --build -d
```

В PowerShell `${PWD}` также обозначает текущую папку. Путь с пробелами оставьте
в кавычках. В Windows можно использовать Docker Desktop с WSL2.

Откройте **http://localhost:3000**. Готовность:

```bash
docker compose ps
docker compose logs app
curl http://localhost:3000/api/health
```

Миграции применяются автоматически перед стартом сервера. База и изображения
сохраняются в именованных Docker volumes, в том числе после `docker compose down`.
**Не используйте `docker compose down -v`, если хотите сохранить данные.**

Необязательные демонстрационные задания (реальные строки в БД, не фиктивные
ответы API, повторный seed не создаёт дубли):

```bash
docker compose exec app npm run db:seed
```

Для проверки отчётов создайте администратора со своим телефонным номером:

```bash
docker compose exec app npm run admin:create -- +79991234567 ADMIN
```

Команда выводит случайно сгенерированный пароль один раз. Известного заранее
пароля нет. Можно заменить `ADMIN` на `MODERATOR`. Существующий аккаунт команда
не повышает автоматически. Войдите этим аккаунтом через обычную форму,
затем откройте кнопку «Проверка заданий и отчётов» или
**http://localhost:3000/moderation.html**.

## Локальный Node.js без контейнера приложения

Требуется Node.js 22.20 или 24 LTS, npm и PostgreSQL 16 (или контейнер БД):

```bash
node scripts/setup.mjs
docker compose up -d db
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run admin:create -- +79991234567 ADMIN
npm run dev
```

Если PostgreSQL установлен отдельно, измените `DATABASE_URL` в `.env` на свой
адрес и заранее создайте базу и пользователя с правами на миграции.
Сборка для обычного запуска:

```bash
npm run build
npm start
```

Не запускайте Node.js и контейнер приложения на порту 3000 одновременно.
Зависимости закреплены точными версиями и `package-lock.json`; используйте
`npm ci`, а не произвольное обновление major-версий.

## Реализованные сценарии

* Гостевой просмотр опубликованных заданий, поиск по названию, описанию и
  адресу; категории и пагинация. Запросы состоят из безопасных параметров Prisma.
* Регистрация по телефону и паролю (минимум 10 символов), вход, выход и
  восстановление сессии после перезапуска сервера. Телефон нормализуется.
* Argon2id (64 MiB, 3 итерации); в ответах API нет хешей и паролей. Проверка
  номера телефона через SMS **не подключена**; номер является идентификатором,
  а не доказательством владения SIM-картой.
* Загрузка JPEG/PNG/WebP до 10 МБ; фактическое декодирование, лимит 20 млн
  пикселей, удаление метаданных и повторное кодирование в JPEG. SVG и исполняемые
  файлы не принимаются. Имена UUID; каталог загрузок не является статическим.
* Предложение задания → проверка модератором → публикация → выбор одним
  исполнителем → фотоотчёт → приёмка или возврат с причиной → начисление баллов.
* Пользователь не может принять собственное задание. Модератор не может
  принимать свой отчёт или отчёт по собственному заданию.
* Отчёт нельзя отправить без фотографии, принадлежащей исполнителю. После
  отказа можно загрузить новое фото и отправить исправленный отчёт.
* Сообщения о мусоре и их статусы сохраняются, проверяются отдельно; баллы за
  одно сообщение не начисляются. Это соответствует финансовой модели проекта.
* Баланс, заработанные за всё время баллы, уровень, история, рейтинг по
  принятым уборкам за всё время/текущий календарный месяц/год (UTC).
* Заявка на вывод от 100 баллов резервирует сумму; отмена или отказ
  администратора возвращает её ровно один раз. Реальная выплата не выполняется.
* Постоянные настройки уведомлений и языка. Напоминания о сроках и уведомления
  о проверке/награде показываются внутри приложения, новые события проверяются
  каждые 30 секунд. Напоминание создаётся при проверке уведомлений за 24 часа
  до срока. E-mail, SMS и фоновые browser push не используются.
* Русский интерфейс; выбор English сохраняется и переводит основные подписи
  форм, навигацию и категории. Развёрнутые пояснения и серверные ошибки пока
  остаются на русском — полноценная английская локализация не заявляется.
* Leaflet с настоящими точками заданий и выбором точки щелчком. Адрес вводится
  вручную: обратный геокодер не подключён. Задания без координат доступны списком.
  Карта показывает максимум 50 заданий выбранной категории; полный список
  доступен через поиск и пагинацию.
* Кабинет модератора и отдельные права администратора для отказов в выводе.

## Принятые допущения

1. Новые участники получают роль MEMBER; роли выдаются только CLI или
   администратором БД. У интерфейса нет законного основания предоставлять роль
   при регистрации, поэтому поле роли в запросах отклоняется.
2. Новые задания требуют публикации модератором. Срок по форме — 7 дней,
   сложность по умолчанию «Легко»; API допускает выбор всех трёх сложностей.
   Сумма — предложение автора, которую модератор оценивает перед публикацией.
3. Фото при предложении задания необязательно (как в исходной форме); фото результата обязательно. Модератор вправе отклонить недостаточно доказательный отчёт. Один исполнитель на задание, повторная отправка возвращённого отчёта возможна.
   Бонус за 10 сообщений из старого макета удалён: источник оплаты не определён.
4. Старые кнопки «выполнить самому» не дают самостоятельно начислять награды:
   открывают список согласованных заданий. Сообщение и задание — разные сущности.
5. Telegram SDK удалён: проверенного входа Telegram в исходнике не было. Браузерная
   авторизация реализована независимо от платформы, без доверия данным WebApp.
6. Нейросетевой приёмки нет. Решение принимает человек; никакие фиктивные оценки
   «80% чистоты» не используются.
7. Баллы — внутренний учёт, а не банковские деньги. API вывода создаёт заявки,
   не переводит средства. Без выбора платёжного провайдера, договора и сведений
   о получателе включить реальные выплаты невозможно. API администратора
   отвечает 503 `PAYOUT_NOT_CONFIGURED` на попытку принять выплату, а не сообщает
   фиктивный успех. В этом проекте нет заглушки, утверждающей успешный перевод.
8. Данные старого localStorage автоматически не импортируются: их нельзя
   считать достоверной идентичностью или балансом.

## Внешние сервисы

Карта использует публичные тайлы OpenStreetMap по HTTPS, без API-ключа.
`MAP_TILE_URL` и `MAP_ATTRIBUTION` позволяют подключить другого провайдера.
Пустой `MAP_TILE_URL` отключает тайлы, список заданий остаётся рабочим.
Тайлы требуют интернета и соблюдения условий провайдера; для публичного
нагруженного сервиса выберите соответствующий тариф/провайдера. Ключ в URL тайлов
является **публичным клиентским токеном**, а не серверным секретом: ограничьте его
по домену. Приватный ключ нельзя помещать в эту переменную.

Google Fonts — необязательная загрузка шрифта, с системным fallback.
Платёжный провайдер, SMS и AI не подключены; учётные данные не запрашиваются и
их работа не имитируется. Приложение полноценно использует БД для перечисленных
локальных сценариев; внешние денежные переводы остаются отдельной интеграцией.

## Безопасность

* HttpOnly-cookie `clnup.sid`, SameSite=Lax, 7 дней; в production — Secure.
  Сессии в PostgreSQL (`session`), ID меняется при входе/регистрации.
* Для любого изменяющего `/api` запроса обязательный заголовок `X-CSRF-Token`.
  Токен выдается `/api/auth/csrf`, привязан к сессии; Origin при наличии
  должен точно совпадать с `APP_ORIGIN`.
* Ограничения попыток входа по IP и телефону хранятся в PostgreSQL и не
  сбрасываются после перезапуска процесса. Загрузка файлов тоже ограничена.
* Zod проверяет типы, диапазоны, длины, UUID; PostgreSQL — уникальность, ссылки,
  допустимые состояния и неотрицательные суммы. Изменения денег и статусов
  используют SERIALIZABLE-транзакции с повтором конфликтов.
* Фотографии доступны владельцу и модератору; исходные фото опубликованных
  заданий доступны гостям. В HTML пользовательские поля выводятся textContent;
  разметка из пользовательских данных не выполняется.
* CORS не нужен: браузер и API на одном origin. Серверные ошибки не содержат
  стеков, SQL, секретов и паролей. Формат: `{error:{code,message,details?}}`.
* HTML содержит старые inline-обработчики, поэтому CSP разрешает inline JS/CSS.
  Пользовательская разметка не вставляется. Для более строгой CSP перед публикацией
  можно перенести inline-обработчики в addEventListener; это не сделано ради
  сохранения структуры приложенного HTML.

## Миграции и сохранение

`prisma/schema.prisma` + `prisma/migrations/202610140001_init/migration.sql`.
Не используйте `db push` вместо миграций рабочего развёртывания.
Новая миграция при разработке:

```bash
npx prisma migrate dev --name describe_change
```

Публикация миграций:

```bash
npm run db:migrate
```

Бэкап: `pg_dump` базы и отдельная копия volume `uploads`. Храните их согласованно.
База содержит ссылки на файлы. Для поиска/удаления старых бесхозных фотографий
нужна политика хранения: автоматическое удаление здесь не включено, чтобы
не уничтожать пользовательские данные. Таблица rate-limit может очищаться
по истекшим `expiresAt`; это не влияет на действующие ограничения.

## Интеграционные тесты

Тесты настоящего API с БД: регистрация, хеширование, CSRF, права,
проверка байтов загрузок, поиск, идемпотентность, публикация,
приёмка/начисление, вывод/возврат, настройки, рейтинг и вход/выход.
Используйте **отдельную** тестовую базу: тесты создают и удаляют свои записи.

После Docker-запуска:

```bash
node scripts/test-compose.mjs
```

Скрипт создаёт `clnup_test`, применяет миграции и выполняет тесты внутри
контейнера приложения. Основная `clnup` не изменяется.

Без Docker:

```bash
# заранее создайте отдельную clnup_test
DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/clnup_test npm run db:migrate
TEST_DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/clnup_test npm test
npm run build
TEST_DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/clnup_test node scripts/verify-restart.mjs
npm audit --omit=dev
```

В PowerShell задайте `$env:DATABASE_URL` и `$env:TEST_DATABASE_URL` перед командами.
Пустой TEST_DATABASE_URL вызывает отказ запуска тестов, а не обращение к рабочей БД.

Для проверки перезапуска:

```bash
docker compose restart app
```

Обновите страницу: аккаунт, задания, история и баланс должны сохраниться.
Перезапуск БД: `docker compose restart db`. Не удаляйте volumes.

## Перед публикацией в интернете

Задайте своё `APP_ORIGIN=https://…`, `NODE_ENV=production`, сильные уникальные
секреты и пароль БД. Поставьте HTTPS reverse proxy, `TRUST_PROXY=1` только при
ровно одном доверенном прокси. В Compose порт приложения привязан к localhost:
reverse proxy на хосте обращается к 127.0.0.1:3000. Не открывайте PostgreSQL наружу.
Не меняйте origin на произвольное `*`. Проверьте Secure cookie через HTTPS.
Настройте резервное копирование, monitoring, условия участия, контакты поддержки,
модераторов, маршрут передачи отходов и политику удаления фотографий/аккаунтов.
Для горизонтального масштабирования нужен общий файловый volume или отдельное
объектное хранилище: локальный uploads рассчитан на один сервер.

## Состав проекта

```
public/                  исходный вид интерфейса + клиент API, Leaflet, кабинет проверки
src/                     Express, безопасность, схемы Zod, Prisma, конфигурация
prisma/schema.prisma     модели и связи
prisma/migrations/       SQL-миграция и ограничения
scripts/setup.mjs        безопасная генерация .env
scripts/seed.ts          демонстрационные задания без аккаунтов/паролей
scripts/admin.ts         создание модератора/администратора
scripts/test-compose.mjs запуск интеграционных тестов в отдельной Docker-БД
tests/integration.test.ts содержательные сценарии API
Dockerfile / docker-compose.yml / .env.example / package-lock.json
```

Подробное соответствие HTML ↔ API — `API.md`. Фактически выполненные проверки
в среде подготовки проекта — `VERIFICATION.md`.
